agentcheck

Agent evaluation · Python · Anthropic SDK

Question: when you grade a tool-using agent from its conversation, what do you miss?

A deterministic back-office world with seven tools and 36 tasks. Every run is graded on the end state of the world, a zero-tolerance policy check over the action log, and the facts in the answer. The environment enforces physics but not policy, so violations happen and get caught rather than being prevented and hidden.

Findings: a grader that reads only the transcript agreed with ground truth worse than chance on the agent that skips checks, passing 16 runs that broke policy and failing every correct refusal. And an agent that looks 96% reliable per attempt gets all eight attempts right on only 75% of tasks.

hybrid-rag-eval

Retrieval evaluation · Python

Question: does hybrid search actually beat BM25?

Four retrieval stacks (BM25, dense, reciprocal rank fusion, fusion plus cross-encoder rerank) on a labelled query set, scored on Recall@k, MRR, nDCG and latency. BM25 and RRF are implemented directly so a result can be attributed to a stage.

The result contradicted the consensus: fusion did not beat its best leg, and BM25 won Recall@3 while running 40× faster. I published it as measured, with the split by query wording that explains why.

rag-document-qa · a companion finding

A similarity threshold is the usual way to make RAG refuse unanswerable questions. Measured on the sample corpus, it can't:

  • 0.907similarity of an off-topic question
  • 0.905similarity of a relevant one

A vocabulary-coverage guard separates them cleanly (0.75–1.00 vs 0.00–0.25), and a test fails loudly if a future embedder makes the simpler guard viable again. Code →

job-radar

Data pipeline · Python · SQLite

Question: of the "remote" jobs on the internet, which can someone in India actually be hired for?

Nine sources (Greenhouse, Ashby and Lever boards for 138 companies, Hacker News, and five aggregators) normalised into one store. Each posting gets an eligibility verdict with a reason and an itemised score whose parts provably add up. History in SQLite flags reposted roles and enforces per-company application caps.

Tailoring is evidence-constrained: the CV generator can only select and reorder facts from a profile file, never write new ones, and a test enforces it.

How I work

Four habits that show up in every repo.

Measure before claiming

Profile before optimising, evaluate before calling something "better". When the numbers disagree with the blog posts, I publish the numbers.

Test the real system

My worst bug passed every HTML-level test while the pricing table was invisible in the browser. Now I verify what users see, and run checks against production.

Reproducible from a clean checkout

No key, no network, no "works on my machine": every AI repo has offline fallbacks, and CI asserts it on each push.

Decisions written where the work lives

Each non-obvious choice goes in the README or commit with the measurement that settled it, so anyone can pick up a thread without a meeting.
